# texgen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or
> superpowers:subagent-driven-development) to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A host-side tool that turns a text prompt into an isomata-ready face
texture (16/32/64 px, palette-quantised, committed-ready) through a staged
pipeline with single-key approvals, backed by a local ComfyUI service.

**Architecture:** A file-based stage contract. Each texture attempt is a run
directory under `.tmp_files/texgen/<slug>/` holding the prompt, stage outputs
(`10-candidates/`, `11-chosen.png`, `20-inpainted.png`, `30-cropped.png`,
`40-pixelated.png`, `50-final.png`) and a `run.json` record. Stages are CLI
subcommands that are pure functions of (run dir, flags): idempotent, resumable,
deterministic given inputs. Generation and inpainting go over HTTP to a local
ComfyUI service; all deterministic image work (crop, pixelate, quantise,
preview) is Pillow in-process. The interface is UI-agnostic so a native bench
(A) or a ComfyUI-native flow (C) can replace only the driver later.

**Tech Stack:** Python 3 (system, 3.14), Pillow 12.2.0, stdlib only otherwise
(`urllib`, `json`, `argparse`, `hashlib`, `shlex`, `subprocess`, `unittest`).
ComfyUI (git clone) in its own uv venv (Python 3.13, torch cu130 for the RTX
3070 Laptop) at `~/proj/comfyui`, models FLUX.2 klein 4B (Apache-2.0) default
and Z-Image-Turbo (Apache-2.0) optional. Viewer: `feh`.

**Spec:** `docs/superpowers/specs/2026-10-10-texgen-design.md` — read it before
Task 1; the plan argues from it and every pinned value below comes from it.

## Global Constraints

- Repo paths are relative to the isomata checkout root
  (`/home/krang/proj/isomata`); run directories live in
  `.tmp_files/texgen/<slug>/` (gitignored). Committed outputs live in
  `assets/textures/` plus `assets/textures/provenance/<material>.json`.
- Target textures are square, power-of-two: 16 (default), 32, or 64. Other
  sizes are rejected, not silently resized.
- The material manifest grammar is exactly
  `material <name> <file> [alpha=opaque|blend|cutout]` or
  `material <name> face <key>=<file> ... [alpha=…]` with keys
  `top bottom north south east west` or `side`. Name is case-sensitive, max 32
  chars (`MATERIAL_NAME_MAX`).
- Exactly one fixed global palette: `tools/texgen/palette.json`, dotty JSON
  format `{"name","author","colors":[[r,g,b,a],…]}`. Quantisation is nearest in
  RGB only; the source alpha channel is preserved; palette alpha ignored;
  dither `none` (default) or `bayer4`.
- The tool never runs `git commit`. It prints the exact `git add` line for the
  human to run.
- Pillow is the only third-party import. `numpy`, `requests`, `websocket-client`
  and `pytest` are not available and must not be used; tests are stdlib
  `unittest`.
- Stages are idempotent and resumable; re-running a stage invalidates its
  downstream outputs (recorded in `run.json`). Same seed + same palette + same
  ops ⇒ byte-identical `50-final.png`.
- In a review prompt, `Enter` accepts, `r` redoes, `q` quits; candidates are
  picked with `1`–`4`. `--yes` accepts everything unattended.
- Commits in this plan add only `tools/texgen/**` (and, for the two asset
  tasks, the exact `assets/textures/**` files named). Never `git add -A`.

## Review Focus

The five input/failure classes below are the ones most likely to bite a user
of this tool and are not obvious from the stage list; each has a test in the
task that owns the code.

1. **`materials.txt` that the human hand-edited** (comments, odd spacing, a
   material declared with `side=`). `manifest.upsert` must preserve the file
   byte-for-byte except the one line it replaces, and never duplicate a
   material. → Task 6 tests.
2. **A crash between writing the PNG and updating the manifest.** Both writes
   are atomic (temp + `os.replace`), and `assign` is re-runnable: a second run
   must converge on the same manifest, not duplicate the line. → Task 6/9 tests.
3. **Palette files from the dotty collection that contain duplicate colours or
   `a < 255` entries.** `palette.load_palette` dedupes and `imops.quantise`
   must ignore palette alpha and preserve image alpha. → Task 4/5 tests.
4. **ComfyUI already running on port 8188** (the human started it, or a
   previous `service start` is still up). `Comfy.ensure_running` must detect a
   live `/system_stats` and never spawn a second instance or wipe its state.
   → Task 11 tests.
5. **`--n 1`, `--n 2`, `--n 3` candidates** (or a retried job that produced
   fewer than the default 4). The montage must lay out any count without
   padding or crashing, and `pick` must accept whatever exists. → Task 5/9 tests.

### Task 5: Deterministic image ops

**Files:**
- Create: `tools/texgen/imops.py`
- Test: `tools/texgen/tests/test_imops.py`

**Interfaces:**
- Consumes: Pillow.
- Produces: `imops.sha256_file(path) -> str`, `imops.load_rgba(path) ->
  Image`, `imops.save_rgba(img, path) -> None`, `imops.crop_center_square(img)
  -> Image`, `imops.crop_rect(img, x, y, w, h) -> Image`,
  `imops.resize(img, size: int, filt: str) -> Image` (`"box"` uses
  `Image.Resampling.BOX`, `"nearest"` uses `NEAREST`; anything else raises
  `ValueError`), `imops.preview(img, factor: int = 16) -> Image`,
  `imops.montage(imgs: list[Image], cols: int = 2) -> Image` (2 columns, 1 px
  gap, last row left-aligned, no padding — geometry must be defined for 1, 2,
  3 and 4 images), `imops.quantise(img, palette, dither: str = "none") ->
  Image`, `imops.is_target_size(size: int) -> bool` (16/32/64 only).

- [ ] **Step 1: Failing tests:** `crop_center_square` of a 30x20 image is
  20x20 taken from the centre; `crop_rect` clips to bounds; `resize(box)` of a
  2x2 image to 1x1 averages all four channels; `resize(nearest)` samples
  source pixels exactly; `preview` of 4x4 by 4 is 16x16 with each source pixel
  replicated 4x4; `montage` geometry for 1–4 images; `quantise` maps every
  pixel to the nearest palette RGB; `quantise` preserves a fully transparent
  pixel's alpha; `bayer4` is deterministic across two runs and differs from
  `none` on a gradient; an unknown filter raises.

- [ ] **Step 2: Run, expect failures.**

- [ ] **Step 3: Implement.** Nearest-colour search is a plain loop over the
  palette (≤64 entries, images ≤1024²); cache a `dict` from packed RGB to
  palette RGB so repeated colours cost one lookup. `bayer4` uses the standard
  4x4 Bayer matrix scaled to ±palette-luma-spread/2, added before the nearest
  search, and only where alpha > 0. `quantise` copies alpha from the source
  pixel verbatim. Deterministic fixture images are generated inside the tests
  with `Image.new`/`putpixel`, never committed as binaries.

- [ ] **Step 4: Run tests; commit** — `feat(texgen): deterministic image ops
  (crop, resize, quantise, preview, montage)`.
